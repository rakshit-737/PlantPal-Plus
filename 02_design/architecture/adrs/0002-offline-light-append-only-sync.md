# ADR 0002: Offline-Light Append-Only Sync Strategy

## Status
Accepted

## Context
PlantPal+ is a mobile and web application. Mobile users often log habits (watering plants, completing workouts, eating meals) in areas with poor or no connectivity (e.g., the gym, the garden). We need a strategy to handle offline writes.
Traditional offline-first solutions involve complex local databases (like WatermelonDB or Realm) and complex conflict-resolution algorithms (CRDTs, last-write-wins, operational transformation) when syncing with the server.

However, the primary data entry interactions in PlantPal+ are **log events**, which are inherently append-only immutable records.

## Decision
We will adopt an **Offline-Light Append-Only Sync Strategy**.
- Clients will cache reads using standard tools (e.g., TanStack Query) persisted locally for offline viewing.
- When offline, any log actions (watering, meals, workouts) will be stored in a simple local queue (Outbox).
- Each logged event will be assigned a `client_idempotency_key` (UUID v4) generated by the client.
- When connectivity is restored, the client will flush the Outbox to the server's sync endpoint.
- The server will process these events with an `ON CONFLICT DO NOTHING` (or upsert) approach based on the idempotency key.

## Consequences
**Positive:**
- Eliminates the need for a complex merge algorithm or CRDTs.
- Conflict-free by construction.
- Significantly simplifies the mobile application state management.
- Safe retries: If the network drops during sync, the client can safely retry the payload.

**Negative:**
- Edits to existing entities (e.g., renaming a plant, editing profile) require an active internet connection, as they are not append-only and could introduce conflicts. This is acceptable per the requirements.
